# Trusted first-order sources

Read this before a web or AI hunt. Search these names. Fetch the page they wrote. Do not ship a roundup about them. Do not add a name from memory and treat it as if it were on this list.

Checked 2026-10-10. A dead URL is a lead, not a source. Fetch it. If it is gone, use the archive steps in the skill.

Places. The research page or the disclosure itself, not a recap:

- YesWeHack. Blog: <https://www.yeswehack.com/blog>. Hunter research: <https://www.yeswehack.com/learn-bug-bounty>. This is the named place. It is not a person, and it is not "SV Hacker".

Start here for SQL injection, XSS, SSRF, IDOR, and the same kind of web class. Then follow who those pages link. A blog found that way can be kept if it passes the skill. A name that is not on this list needs the extra-fetch judgment in the skill.

## AI security and AI harness

Use this order. Stop when the earlier step is enough.

1. The product's own docs. Claude: <https://docs.anthropic.com/>, Claude Code: <https://code.claude.com/docs>, engineering: <https://www.anthropic.com/engineering>. Another product: that vendor's own docs, not a blog about them.
2. Google's official courses and docs. The course or the doc, not a summary of it.
3. A reputed GitHub repo. The repo itself.
4. A paper. List title, authors, and URL only. Do not open posts about the paper.

## Not first-order

Drop these unless the skill's unknown-author rule survives extra fetches:

- "Complete guide", listicle, and "what I learned from" posts
- A page that restates PortSwigger, Intigriti, or a hunter and adds no new trace
- Medium, unless the Medium rule in the skill passes
- A paper summary when the paper itself is public
